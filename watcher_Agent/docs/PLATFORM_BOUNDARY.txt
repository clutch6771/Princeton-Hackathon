PLATFORM BOUNDARY (2026-11-14)
==============================
AttentionAgent/ implements native capture and local notifications. The Python
Judge only receives evidence, interprets it and persists verdicts. The model
has no tools and cannot request screenshots, microphone access, capture,
notifications, SQL or memory changes.

Current native implementation
-------------------------------
SampleHandler.swift: user-started ReplayKit Broadcast Upload Extension.
Shared/ReelTracker.swift: local boundaries, privacy text screening and one
JPEG sample per exposure; network JPEG longest edge is <=512 pixels.
Shared/ReelAudioTranscriber.swift: device speech recognition of app audio.
Shared/LiveAgentBackend.swift: completed-reel JSON uploads to /agent1/ingest,
identity header, /timeline checkpoint data and /feedback corrections.
SampleHandler flushes, drains queued uploads and requests /session/end on
stop; iOS may terminate an extension before a network request finishes, so
the backend's idle timeout remains required.
Shared/AgentBridge.swift and App/CheckpointNotifier.swift own notifications.
App Groups exchange observations/settings. Live backend is opt-in; other
APIClient/mock demo paths still exist and do not verify the real server.
Coach chat still points to /agent2/chat, outside Judge ownership.

PRD target path (server implemented; native stream adapter remains pending)
--------------------------------------------------------------------------
One 512px JPEG every 2s and independent 5s 16kHz mono AAC chunks to multipart
/ingest/frame and /ingest/audio. The server handles timestamp alignment,
segmentation, permitted audio assembly and selection of up to 3 frames.
The native /agent1 path already segments on device and is not segmented again.
It sends one JPEG + partial speech text, not the PRD's full multimodal clip.
Do not claim raw audio interpretation or 2-3 frame coverage for that path.

Privacy capability
------------------
Current legacy JSON uploads lack a certified Reels-only gate. The adapter
labels this dev_fake. They work only in explicit development/dev_permissive.
Production rejects them until the platform supplies PrivacyProvenance from a
real gate. Check every interval: DMs/other apps must be discarded BEFORE
upload, including audio. Never mark the existing text-screening heuristic as
a trusted feed gate. Microphone audio is not part of the product.

Device verification still required
-----------------------------------
Real Instagram app audio availability; accurate per-reel transcript boundaries;
native eligibility gate; under-50MB extension memory for 10 minutes; signing
and App Groups; notifications during broadcasting; real frame segmentation;
notification timing relative to asynchronous completed judgments. Synthetic
Python tests do not establish any of these device properties.
