PRD TRACEABILITY
================
Baseline: Values-Aligned Attention Companion PRD, 2026-11-14, as restated in
the Judge implementation prompt. Where the older PDF snapshot differs
(frames only, MongoDB, 3-in-5 drift, 2-minute cooldown, /observe, 4-second
latency), the newer statements were followed.
Kinds: PRD = requirement, INT = operational interpretation, ENG = engineering
setting, DEF = deferred to another owner. Paths are under watcher_Agent/.
Tests are under tests/ (unit/ unless noted).

Engineering settings (ENG): every number not listed as a PRD default in
MEMORY_PARAMETERS.txt section E, including model ids, size caps, RAM limits,
segmentation thresholds, deadlines, retries and lease times.

Deferred (DEF), not implemented here:
  Native iOS/Android capture, native eligibility gate, banners   platform owner
  Guardian chat, onboarding, value proposals and approvals       Guardian owner
  Reflector, session summaries, hypotheses, briefs, questions    Reflector owner
  Daily re-rating scheduler, GUI, Share Extension, PiP, shield   other owners
  /chat, /values, /share endpoints                               other owners
  Value-concept-vector feedback retrieval                        later (seam exists)

Verified by tests (synthetic data): everything in the table above.
NOT verified:
  - Real Instagram frames and audio; segmentation thresholds on real feeds.
  - Native memory use (50 MB) and physical-device capture.
  - Gemini: live calls were not run (no API key). Model id, structured
    output with images + audio, quota and judgment quality are unverified.
  - pgvector: not installed on the test machine, so vector storage and
    nearest-neighbour SQL were not executed against PostgreSQL (they run
    against the in-memory backend only).
  - Tiger Data cloud itself (tests used local PostgreSQL 17).
  - Notification banners and delivery timing on a device.
