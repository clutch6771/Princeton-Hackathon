JUDGE EXECUTION FLOW (2026-11-14)
=================================
Input comes from native capture; the Judge never captures a screen or audio.
Output is a persisted verdict with reasons; the Judge never sends a warning.

1. Admit external evidence and authenticate the demo user.
   Stream: /ingest/frame and /ingest/audio validate metadata, cap body/media
   sizes and screen privacy provenance before provider use. Receipts give
   idempotency; capture clocks align independently of the server clock.
   Completed reel: /agent1/ingest accepts the current Swift payload, gates its
   provenance, validates JPEG bytes and uses session + reel_index as stable
   identity. Native boundaries are preserved; no second segmentation pass.

2. Prepare one exposure, in RAM only.
   Stream path segments frames using whole-frame changes plus supporting
   evidence, aligns permitted PCM intervals and waits a bounded final-audio
   deadline. Select up to 3 frames and assemble a WAV clip.
   Completed-reel path uses its one sampled frame and optional native speech
   transcript. Its raw audio is missing; transcript coverage remains partial.
   Both paths enqueue the same JudgeJob. Queue and media memory are bounded.

3. Read approved values, pin their content hash and revision.
   Default: Guardian's protected (user_id, guardian, values) Store namespace.
   Explicit document compatibility: (user_id, memories), key values.md.
   Never infer values from stated_goals, sensitivity, captions or behaviour.
   Unavailable/invalid values are a distinct failure, not neutral.

4. Retrieve at most 3 recent explicit feedback examples for this revision.
   This is a labeled recency fallback, not semantic nearest-neighbour lookup.

5. Make one joint understanding/judgment call on the normal path.
   Grok receives frames and approved values/examples. Supplied waveforms go
   first to xAI STT; their speech text is untrusted input to Grok. Thus Grok
   audio uses two HTTP requests (one judgment). Gemini can perform the joint
   multimodal call. Native transcripts skip STT. No model tools, capture,
   notification decision or repair call. Bounded provider retries remain.
   Treat visible text and speech as untrusted evidence, never instructions.

6. Validate value IDs, finite confidence, reason, features and evidence.
   Without audio, model-invented speech is rejected. Native transcript text
   is retained verbatim as partial, distinct from missing waveform coverage.
   Failed judgments have verdict=null with an explicit evaluation_status.

7. Atomically persist one terminal outcome, one sanitized thumbnail, optional
   embedding work and session counts. The capture-order cursor counts each
   finalized reel once and tolerates deleted sequence gaps. No batching,
   cooldown, notification text, outbox or delivery exists in this transaction.
   Release volatile media on success, failure, overload and shutdown.

8. Embed stored description + transcript asynchronously, with bounded retries.
   The app reads /timeline and /thumbs. Guardian reads the same real records
   through JudgeDataSource; feedback writes use the shared FeedbackService.

9. End the session explicitly (/session/end) or after 600 idle seconds.
   Flush the stream tail, finish pending jobs, write one session_completed
   event with counts. No direct Guardian/Reflector call. Backend integration
   consumes that event. Restart loss and stuck jobs are explicit outcomes.

Notifications remain owned by AttentionAgent/SampleHandler.swift,
Shared/AgentBridge.swift and App/CheckpointNotifier.swift. They consume
verdicts; they are not generated by the Judge.
